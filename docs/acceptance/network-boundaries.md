# 网络边界加固与兼容回归

## 范围

本补丁在发送请求前约束平台 API 目标和媒体上传请求头。它是防御性加固，
不是对 Registry 三条扫描命中的漏洞确认，也不代表 Registry 已经放行。

兼容基线是已发布的 1.0.0，提交 `230ceb62093b5ed650b7afba0b6a5a9e22a18a45`。
前一轮代码和回归验证保持 1.0.0，未发布。本轮经负责人授权准备 1.0.1，
在最终 main 提交的 CI 和验收通过后，继续通过既有 `publish.yml` 正式发布。
新增付费任务仍需符合已批准的具体配置、次数和预算，历史证据保留原版本归属。

## 行为约束

- 平台 API 仍使用 `https://api.cuddler.ai`。每次请求在添加凭据、编码请求体和调用传输层前，
  检查 HTTPS、主机、端口及 origin 不能包含的路径、查询或片段。
- 检查和发送使用同一份 origin 快照，客户端属性在请求过程中变化也不能改变本次目的地。
- 媒体 URL 沿用现有存储域名检查。上传使用同一份检查后的请求头快照，拒绝
  `Authorization`、`Cookie`、`Proxy-Authorization` 和无效的请求头名称、换行注入。
  合法签名存储请求头及签名 URL 原样保留。
- 系统代理、HTTPS CONNECT、禁止重定向、响应大小与流式下载限制沿用原实现。
- 四类节点、参数、工作流、模型目录、输出类型和价格/限额流程不变。
- SQLite 表结构、文件位置、初始化标记、运行指纹、凭据绑定、幂等键、
  上传复用、轮询、取消与清理策略不变。

## 必需回归

| 范围 | 预期结果 |
| --- | --- |
| 默认 API 和合法 HTTPS origin 写法 | 请求方法、URL、请求头、请求体、限额与超时保持一致 |
| 外站、仿冒域名、HTTP、用户信息、额外路径、查询、片段 | 传输层未收到请求；不发送凭据或提示词 |
| 请求编码期间 origin 变化 | 本次请求只发往已检查的地址；下一次调用重新检查 |
| 错误 origin 修正后重新运行 | 失败未占用任务记录，修正后仍能正常提交一次 |
| 恶意或无效媒体上传请求头 | 任何媒体 PUT 之前报 `invalid_response` |
| 合法签名上传头、签名 URL 和下载 | 保留签名内容；不把平台认证附加到媒体请求 |
| 系统代理运行中切换、重定向、断流、磁盘写入失败 | 原有测试结果保持一致 |
| 重启、并发、旧响应、密钥轮换、未知提交 | 恢复原任务；保留原幂等键；不重复创建收费任务 |
| 损坏、空白或丢失的已初始化数据库 | 保留证据并停单；不静默重建 |
| 旧版写库 → 候选恢复 → 旧版回退恢复 | 四类原任务只读恢复；任务 ID、幂等键、凭据绑定一致 |

优先复用 `tests/test_client.py`、`tests/test_transport.py`、`tests/test_jobs.py`、
`tests/test_uploads.py`、`tests/test_state.py`、`tests/test_runtime.py` 和已有宿主/浏览器检查。
新增边界测试应能拒绝原基线的对应行为，不能只验证新实现自身。

## 检查入口

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -t . -v
npm test
```

公开目录联网检查默认跳过，不能把它写成真实 API 联调通过。
完整 CI 继续使用 `test.yml` 的三系统 × 三版 Python 和前端测试，
以及 `host.yml` 的 ComfyUI 0.14.0 / 0.40.0 宿主与浏览器检查。
这些宿主检查使用受控平台替身，不生成供应商任务、不验证真实账单结算。

验收记录必须绑定最终候选 SHA，分别列出本地测试、跨版本对照、完整 CI、
实际宿主检查及未执行的真实联调。出现正常请求差异、恢复记录丢失、重复提交、
代理不可用或旧工作流无法加载时，停止进入发行。

## Registry 与后续发行

正常 HTTP 和 SQLite 调用仍然明确可见。不会通过改名、隐藏字符串、动态调用、
移除 SQLite 或删除恢复记录来改变扫描结果。
公开复核记录：<https://github.com/Comfy-Org/registry-backend/issues/298>。

本补丁通过回归不等于 Registry Active，也不等于新版本已获发布授权。
后续版本提升与正式发行应单独审阅，继续使用既有固定 SHA 和验收引用门禁。
回退需要保留整个私有状态目录，不通过删除数据库或幂等记录重试。
